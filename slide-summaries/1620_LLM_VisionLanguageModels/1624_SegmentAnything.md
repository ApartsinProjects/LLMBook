## Slide 1 — Segment Anything Model
Title slide for SAM (Prompt-table segmentation).

## Slide 2 — Task: Zero-shot Segmentation
SAM finds a mask of an object in an image described by text ("big dog"), a point, a box, an approximate mask, or any combination. Training data (images plus masks) is generated through three escalating stages: assisted-manual (SAM proposes, human edits), semi-automatic (SAM creates masks, annotator adds missed ones), and fully automatic (human prompts with a grid of mask "centers"; SAM auto-generates the masks). The model is gradually fine-tuned with more automatic data as it improves, with more masks generated per image.

## Slide 3 — Data: images and masks
A figure of the SAM training-data structure: images and masks.

## Slide 4 — Architecture
Image encoder: pretrained ViT. Prompt encoders include a sparse one (embeds boxes / points with positional encoding), a dense one (spatial integration, embedded into the same dimension as patches and added to patch embeddings), and a text prompt encoder (uses CLIP encoding for text).

## Slide 5 — Lightweight Mask Decoder
Input is a query sequence: prompt tokens, image patch embedding (including mask prompt), dense prompt embeddings (bbox and points), projected CLIP text embedding, mask tokens (learnable query vectors, one slot per mask candidate, for example three slots), and a special IoU token (used to predict scalar quality of each generated mask). All tokens share dimension. Output is processed mask tokens and the IoU token: one output token per mask produces the actual masks via a multi-step process, and the IoU head produces a score per mask.

## Slide 6 — Generating Mask Images
From processed tokens and image embeddings (1024x1024 image, 16x16 patches, 64x64 vectors): upsample the image embedding from 64x64 to 256x256, project each mask token to a vector v of the image-embedding dimension, multiply each patch embedding by v producing one number per patch (256x256), scale up to the original size (1024x1024), and apply sigmoid to get binary mask values.

## Slide 10 — FastSAM
SAM's ViT encoder with 2B parameters makes it slow. FastSAM uses a CNN-based YOLO backbone with the YOLACT (You Only Look At Coefficients) method. The prompting model is inverted: segment everything first without prompts, then apply prompts during post-processing after all objects and masks are created.

## Slide 11 — Background: Feature Pyramid Network
A CNN naturally produces more coarse features in deeper layers (global information). To get local features that contain both global and local information, upsample coarse layers and add to the previous layer.

## Slide 12 — YOLACT
YOLACT has two branches. The prototype mask branch creates a set of "basis" segmentation masks. The prediction branch predicts the bounding box, estimates prototype coefficients, and linearly combines prototype masks. For each anchor it predicts class distribution, box regression (with NMS to filter duplicate detections), and mask coefficients.

## Slide 13 — FastSAM
A protonet (lightweight CNN) outputs a [H, W, K] tensor with K = 32 masks for the entire image.

## Slide 14 — Prompt Guidance Post-Processing
Post-processing for a point prompt filters out masks that do not contain the point and merges all masks that do. For a box prompt, filters out masks whose bounding box does not have high IoU with the prompt. For text, computes CLIP embeddings of the text and of the mask area and returns masks with high similarity.

## Deck-level takeaway
SAM (Segment Anything Model) is a foundation model for image segmentation that accepts heterogeneous prompts (text, point, box, mask) and produces multiple candidate masks plus an IoU quality score per mask. Its three-tier data engine (assisted, semi-automatic, fully automatic) bootstraps an enormous mask dataset from a smaller seed. The deck contrasts this with FastSAM, which trades SAM's heavy ViT backbone for a CNN-based YOLO / YOLACT pipeline that generates all masks first via a prototype-and-coefficient decomposition and applies prompt guidance only as post-processing (point containment, IoU filtering, CLIP-based text similarity), exposing all of this through the Ultralytics library.
