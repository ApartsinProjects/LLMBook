Exercise 1.4.1: Polysemy Resolution by Layer Conceptual

The "bank Across Layers" callout shows that ELMo's lower layers cluster by surface morphology while upper layers cluster by semantic role. (a) Predict what each layer would do with the word "light" across these three sentences: "the light bulb burned out", "the suitcase felt light", "her tone was light and playful". (b) Which layer would you use as features for a part-of-speech tagger and which for word-sense disambiguation? Why?

Answer Sketch

(a) Layer 0 (character CNN) gives the same vector in all three: it only sees the string "light". Layer 1 (lower BiLSTM) starts to differentiate by neighbouring syntax: "light" as noun in sentence 1 versus adjective in 2 and 3. Layer 2 (upper BiLSTM) distinguishes the meanings: illumination in 1, low-weight in 2, casual-tone in 3. (b) For POS tagging use the lower BiLSTM layer because POS is mostly a syntactic property determined by local neighbours. For word-sense disambiguation use the upper BiLSTM layer because senses are semantic and depend on broader context. The "Choosing the Right Layer" callout makes this concrete: ELMo's learned scalar mixture lets a downstream task discover the right per-layer weighting automatically.

Exercise 1.4.2: Static-vs-Contextual Cosine Math Calculation

You compute cosine similarity for the word "bank" between two sentences: "I deposited cash at the bank" and "we sat by the river bank". With static embeddings (word2vec) you get a single vector for "bank", so the cosine similarity between the two occurrences is exactly 1.0. With ELMo or BERT, the cosine drops to around 0.4-0.6. (a) Explain why a number greater than zero is the expected, correct outcome for contextual models, not a bug. (b) What single experiment would convince you that the contextual model is genuinely separating senses rather than just adding random noise?

Answer Sketch

(a) The two occurrences share the surface form, the syntactic role (noun), the part of speech, and the orthography, all of which the lower layers correctly encode. They differ only in semantic sense, which the upper layers separate. A cosine of 0.5 is the right balance: not 1.0 because the senses differ, not 0.0 because almost everything else is identical. (b) Construct a probe: collect 100 financial-bank sentences and 100 river-bank sentences, extract contextual vectors, run a logistic regression on the binary sense label. If the model is genuinely sense-separating, classification accuracy will be near-perfect with very few features; if the cosine drop were noise, classification accuracy would hover near chance. This is exactly the methodology of the WSD probing literature (e.g., Pilehvar and Camacho-Collados 2019).

Exercise 1.4.3: Why BERT Replaced ELMo Failure Mode

The "Why We Used BERT Instead of ELMo" callout notes that production teams stopped reaching for ELMo within ~12 months of BERT's release. List three concrete architectural or workflow advantages BERT had, and one specific use case where ELMo's design might still be preferable today.

Answer Sketch

Advantages: (1) Parallelism: ELMo's BiLSTM is sequential, processing token t only after token t-1, so GPU utilization is poor. BERT's transformer attends to all positions in parallel and trains 5-10x faster on the same hardware. (2) Bidirectional context fusion: ELMo concatenates left-to-right and right-to-left LSTMs after the fact; BERT's masked language modeling lets every layer attend bidirectionally from the start, producing richer representations. (3) The pretrain-then-fine-tune workflow: BERT is fine-tuned end-to-end with a task head, replacing ELMo's "extract features and train a downstream BiLSTM" pipeline. ELMo is still preferable when you need a small, CPU-friendly model with no quadratic memory cost: long documents (10k+ tokens) on resource-constrained hardware where transformer attention's O(n^2) is prohibitive. Most teams now use distilled transformers (DistilBERT, MiniLM) for that niche instead.

Exercise 1.4.4: Probing the Contextual Vectors Code Tweak

The section's medical NER vignette uses contextual embeddings to disambiguate drug names. Sketch a 10-line PyTorch snippet that, given a sentence and a target token index, extracts the BERT-base contextual vector for that token from the last layer. Then describe one common bug that produces a vector with the wrong shape or wrong content.

Answer Sketch

Sketch:
from transformers import AutoTokenizer, AutoModel; import torch
tok = AutoTokenizer.from_pretrained("bert-base-uncased")
m = AutoModel.from_pretrained("bert-base-uncased").eval()
enc = tok("The patient takes Tylenol", return_tensors="pt")
with torch.no_grad(): out = m(**enc)
vec = out.last_hidden_state[0, target_idx] # (768,)
Common bug: the user's word index is the word position in the original sentence, but BERT's tokenizer subword-splits "Tylenol" into "ty", "##len", "##ol", so the original word index does not align with the model's token positions. The fix is to call tok(..., return_offsets_mapping=True) or to use the slow tokenizer's word_ids() method, then average or pick the first subword vector. Forgetting this misalignment is the most common cause of "my NER results are nonsense" in early BERT pipelines.
