Exercise 2.3.1: Special Token Bug Hunt Failure Mode

The "Chat Template Mismatch Causes Silent Quality Degradation" callout describes a team that wrote their own chat template and saw 15-20% accuracy regression. (a) Sketch what their wrong template might have looked like for a Llama-3 model and what the correct one looks like. (b) Why is the failure silent (no error, no warning, just lower quality)? (c) Name the single line of Hugging Face code that prevents this entire class of bug.

Answer Sketch

(a) Wrong: "USER: {prompt}\nASSISTANT: ", an Alpaca-style template borrowed from a tutorial. Correct Llama-3: "<|begin_of_text|><|start_header_id|>user<|end_header_id|>\n\n{prompt}<|eot_id|><|start_header_id|>assistant<|end_header_id|>\n\n". The special tokens are not optional; the model was trained to condition on these exact byte sequences. (b) The model still generates fluent text because next-token prediction degrades gracefully: it just samples from a less-instruction-aligned distribution, so outputs are plausible but less helpful. There is no exception, just slow quality decay that only shows up in evaluation. (c) tokenizer.apply_chat_template(messages, add_generation_prompt=True). The tokenizer ships with a Jinja template authored by the model creators that produces the exact byte sequence the model expects. The "Always Use the Official Template" warning is not optional advice.

Exercise 2.3.2: Multilingual Fertility Math Calculation

The fertility lab compares tokens-per-word across languages. Suppose your benchmark text is 1000 English words and the GPT-4 tokenizer produces 1300 tokens. The same text translated to Russian gives 3100 tokens; to Thai it gives 5200 tokens. (a) Compute fertility (tokens/word) for each language. (b) For a chat product priced at $0.01/1k input tokens, what is the per-message cost ratio between Thai and English? (c) What does Llama-3's tokenizer do differently from GPT-2's that narrows but does not eliminate this gap?

Answer Sketch

(a) English fertility = 1.3 tokens/word. Russian = 3.1. Thai = 5.2. (b) The Thai user pays 5200/1300 = 4x what an English user pays for the same semantic content. If the prompt budget supports 1000 English messages, it supports 250 Thai messages. (c) Llama-3 expanded its vocabulary from 32k (Llama-2) to 128k tokens, with explicit training on a more balanced multilingual mixture and weighted byte-level BPE that allocates more vocabulary slots to non-Latin scripts. This typically halves the fertility for languages like Chinese, Russian, and Hindi while keeping English fertility roughly constant. Thai still suffers because it has no spaces between words, which forces longer subword sequences regardless of vocabulary balance. Cohere's Aya and the Sarvam family go further by training tokenizers specifically for South Asian scripts.

Exercise 2.3.3: Cost Estimation in Production Code Tweak

The "Token-Aware Prompt Engineering Cuts API Costs by 40%" callout describes a team that pruned redundant context. Sketch a 5-line Python function that, given a list of strings, returns the GPT-4 token count using tiktoken and the dollar cost at $5/M input tokens. Then describe the single most impactful prompt-shrinking technique that does not require retrieval.

Answer Sketch 
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
def cost(strings, price_per_million=5.0):
  total_tokens = sum(len(enc.encode(s)) for s in strings)
  return total_tokens, total_tokens * price_per_million / 1_000_000

The single most impactful prompt-shrinking technique without retrieval is few-shot example pruning: most production prompts carry 10+ few-shot examples that contribute marginal accuracy gain past 3-5 examples. Cutting from 10 to 3 examples typically saves 30-60% of input tokens at <1% accuracy cost. The next biggest wins are removing verbose system prompts ("You are a helpful, harmless, and honest assistant who...") and switching from JSON to TSV for structured output formats, which cuts output tokens by 30-50%.

Exercise 2.3.4: Multimodal Tokenization Equivalence Conceptual

The "Universal Language of Tokens" callout argues that image patches, audio codec frames, and text subwords are all just "tokens" to the transformer. (a) Estimate the token count for a 224x224 ViT image with patch size 16. (b) For a 30-second audio clip at the EnCodec rate of 75 tokens/second/codebook with 8 codebooks, what is the total token count? (c) Why does this unification matter for cross-modal reasoning, and what is the failure mode when one modality dwarfs the others in token count?

Answer Sketch

(a) ViT-Base patches a 224x224 image into 14x14 = 196 patches plus 1 CLS token = 197 tokens. (b) 30 s * 75 tokens/s * 8 codebooks = 18,000 tokens. (c) Unification means a single transformer can attend across modalities (an image and its caption become one sequence) and reuse all the engineering work on attention, KV caching, and sampling. The failure mode is token-count imbalance: at 18k audio tokens vs. ~50 caption tokens, the audio dominates the attention budget, the gradient signal from text gets drowned out, and the model essentially ignores one modality. Production systems address this with hierarchical tokenization (Whisper's encoder-decoder split), pooling layers that compress one modality before fusion, or attention masks that force balanced cross-modal attention.
