Exercise 36.6.1: Documentation as a Steering Wheel Conceptual

Traditional documentation is a write-up of the system. AI-era documentation is also a control surface that steers the system. (a) Explain the difference with a concrete example. (b) Why does this only matter once LLM agents read your docs at runtime or build-time? (c) What is one machine-readable artifact every LLM-driven product should ship?

Answer Sketch

(a) Traditional: README.md describes how the deployment pipeline works for humans. Steering: a RUNBOOK.md with step-by-step procedures that an LLM agent can read, follow, and execute (e.g., for incident response). The same content; very different downstream effect. (b) When humans read docs, the docs are passive. When agents read them, every word of the doc directly shapes runtime behavior; the doc is the prompt. (c) The minimum machine-readable artifact: an OpenAPI or JSON schema for every external interface, plus a structured capabilities manifest (what the system can and cannot do). These let any future agent integrate without ambiguity, dramatically reducing prompt-engineering tax in tool-use settings.

Exercise 36.6.2: Predict the Compliance Drift Predictive

You publish an Intent + Evidence Bundle (IEB) for an AI feature: intent statement, eval results, known limitations, monitoring SLOs. Predict: (a) what part of the IEB drifts first; (b) the standard cause; (c) the cheapest mitigation.

Answer Sketch

(a) The eval-results section drifts first: the published numbers were measured at one snapshot, and the underlying model, prompts, or data shift over time. (b) The standard cause is human inattention: nobody reruns the eval after every change, and so the IEB silently becomes stale, sometimes by 5-15 percentage points. (c) Cheapest mitigation: a CI job that reruns the headline eval on every release and either updates the IEB automatically or fails the release if numbers drop more than a threshold. Treat the IEB as code, not as a one-time deliverable. Audit-grade documents must be regenerated from machine-readable sources, not maintained by hand.

Exercise 36.6.3: Build an IEB Validator Code Tweak

Sketch a 12-line script that loads an IEB (YAML) and a pointer to the eval-result JSON, then verifies (a) the eval was rerun within the last 30 days, (b) all SLOs are still met, (c) any "limitation" entries match real failure-class IDs in the eval. Output: pass/fail with a structured report.

Answer Sketch

import yaml, json, datetime as dt
ieb = yaml.safe_load(open("ieb.yaml"))
eval_res = json.load(open(ieb["eval_path"]))
age = (dt.datetime.now() - dt.datetime.fromisoformat(eval_res["timestamp"])).days
fails = []
if age > 30: fails.append(f"eval is stale ({age} days)")
for slo in ieb["slos"]:
  actual = eval_res["metrics"][slo["metric"]]
  if actual < slo["threshold"]: fails.append(f"{slo['metric']}: {actual} < {slo['threshold']}")
known_classes = set(eval_res.get("failure_classes", []))
for lim in ieb.get("known_limitations", []):
  if lim["failure_class"] not in known_classes: fails.append(f"unknown limitation: {lim['failure_class']}")
print(json.dumps({"pass": not fails, "failures": fails}, indent=2))
The validator is a 50-line CI job that turns governance from "trust the docs" into "verify the docs". Treat any IEB-validation failure as a release blocker for high-stakes features.

Exercise 36.6.4: Documentation Failure Modes Failure Mode

List four documentation patterns that look complete to humans but mislead LLM agents, with one mitigation per pattern.

Answer Sketch

(1) Implicit assumptions: "the user is logged in" is assumed by the prose but never stated. Agent attempts the workflow without auth and fails. Mitigation: write preconditions explicitly. (2) Out-of-date examples: code examples reference a deprecated API. Agent emits the broken call. Mitigation: doctest the examples in CI. (3) Ambiguous wording: "this is usually fine" lets agents skip safety checks. Mitigation: replace soft-language with explicit conditionals ("if X then Y"). (4) Missing failure modes: no documentation of the rate-limit response. Agent retries indefinitely. Mitigation: document every error class with the agent-action expected. The general principle: docs that pass human review can still mislead agents because agents lack the contextual judgment that fills in human gaps.
