Exercise 7.4.1: Why Multilingual Models Work At All Conceptual

A single model can speak English, Mandarin, and Swahili from one set of weights. (a) What architectural mechanism allows cross-lingual transfer at all, given that these languages share almost no vocabulary? (b) Why does training on more English data sometimes improve performance on a low-resource language? (c) When does this transfer effect break down?

Answer Sketch

(a) Subword tokenization (BPE/SentencePiece) creates a shared vocabulary at the byte level, and the model learns shared abstract representations in higher layers (concept of "noun", "negation", "tense") that are language-agnostic. (b) English data is so much larger and higher quality that it teaches the model general world knowledge and reasoning patterns; the multilingual weights then translate that knowledge into the target language at inference time, even without parallel data. (c) Transfer breaks for languages with very different morphology (agglutinative or polysynthetic languages), unique scripts with poor BPE coverage, or domains where the shared abstractions don't match (formal vs. informal registers vary by language). For these cases, dedicated multilingual training mixes or per-language fine-tuning is required.

Exercise 7.4.2: Predict the Tokenizer Tax Predictive

The same paragraph in English tokenizes to 100 tokens with cl100k_base. Predict the token count for the same content in: (a) German; (b) Japanese (kanji-heavy); (c) Hindi (Devanagari script). What is the operational implication for non-English users?

Answer Sketch

(a) German: ~120-140 tokens. Long compound words split into more subwords than English. (b) Japanese: ~150-200 tokens. CJK characters often get one or two BPE tokens per character, much worse than English's 1 token per ~4 characters. (c) Hindi: ~250-400 tokens. Devanagari coverage in English-centric tokenizers is poor; many characters fall back to byte-level UTF-8 encoding (3 bytes/char). Implication: per-message API costs are 2-4x higher for non-English users, and the effective context window shrinks proportionally. Fixes include language-specific tokenizers (e.g., Sarvam for Indic) or models trained with rebalanced tokenizer training data.

Exercise 7.4.3: Add Language Detection Routing Code Tweak

Sketch a 6-line dispatcher that detects the language of an incoming message and routes to a language-specific model when one is available, else falls back to GPT-4o. Use fasttext or langdetect for the detection. What edge case must you handle?

Answer Sketch

from langdetect import detect
specialists = {"hi": "sarvam-2b", "ja": "rakuten-7b", "ar": "jais-13b"}
def route(msg):
  try: lang = detect(msg)
  except: lang = "en"
  return call_model(specialists.get(lang, "gpt-4o"), msg)
The edge case: code-mixed messages (e.g., Hinglish: Hindi sentences with English nouns embedded). langdetect picks one label, which routes to the wrong specialist and produces poor output. Mitigation: detect language confidence; if low (<0.7), default to the multilingual frontier model. For known code-switched user bases, train or fine-tune specifically on the mixed register.

Exercise 7.4.4: Cultural Bias Failure Modes Failure Mode

You deploy a global chatbot trained primarily on English web data. List four cultural-bias failure modes you should test for before launch, with one concrete test for each.

Answer Sketch

(1) Western default values in advice: model recommends individualistic solutions to questions framed in collectivist contexts. Test: ask the same advice question framed in different cultural contexts and check answer variation. (2) Name and demographic stereotyping: occupations or attributes correlate with names. Test: pair-prompt with name swaps and measure differential outputs. (3) Holiday and date assumptions: assumes US/UK calendar, ignores Lunar New Year, Diwali, Eid. Test: temporal queries from different geographies. (4) Address and form formatting: insists on US-style ZIP codes, phone formats. Test: structured-output benchmarks per locale. The common pattern: build a localization eval set that includes these axes, not just translated MMLU.
