Libraries & Frameworks

Section 12.2

Part II is the chapter where you need to actually read and modify weights. The libraries below are split into three groups: tokenizer libraries (used in Chapter 8 to compare what different model families see), interpretability libraries (used in Chapter 11), and inference-optimization libraries (used in Chapter 10).

12.2.1 Tokenizer libraries

The three tokenizer libraries you need in practice are tiktoken, SentencePiece, and the Hugging Face tokenizers library. tiktoken is OpenAI's open-source tokenizer; it ships the BPE tables for GPT-2 through GPT-4o (o200k_base) and is the fastest way to count tokens before you pay for them. SentencePiece is Google's tokenizer; it powers T5, Llama, Mistral, Gemma, and most Asian-language-friendly models because of its built-in support for the unigram language model and byte-fallback. Hugging Face tokenizers is the most general: it wraps BPE, WordPiece, Unigram, and SentencePiece behind one API and ships the Rust implementations that AutoTokenizer.from_pretrained calls underneath.

You will not usually pick one explicitly. The model card tells you which tokenizer the checkpoint expects, and AutoTokenizer picks the right backend. When you do need to choose (training a tokenizer from scratch on your own corpus, comparing vocabularies across model families), the choice maps to the algorithm: BPE for English-heavy web data, Unigram/SentencePiece for code or multilingual data, WordPiece if you specifically want BERT-compatible output.

12.2.2 Interpretability libraries

The two libraries that dominate post-2024 interpretability work are nnsight from the National Deep Inference Fabric and TransformerLens from Neel Nanda's group. nnsight exposes any PyTorch module's internal activations as Python objects under a context manager and supports remote inference on hosted large models, which is the only practical way to do mech interp on frontier-scale weights. TransformerLens reimplements a curated set of architectures (GPT-2, Pythia, Llama variants) with explicit hook points and standardized activation names; it is the library most published mech-interp papers cite as of 2026. For sparse autoencoder work specifically, SAELens adds training and evaluation utilities on top.

Chapter 11 walks through using these libraries to extract activations, patch them, and train SAEs. Appendix F covers the Hub-side integration.

12.2.3 Inference-optimization libraries

Part II's Chapter 10 on inference optimization names three libraries explicitly: vLLM (the PagedAttention reference implementation), SGLang (the newer entrant with better structured-output support), and Hugging Face TGI (the production-ready serving stack). All three are covered properly in Chapter 36's tools list; here they appear because you may want to benchmark them on the Part II workloads.

12.2.5 Practical notes

For most users, just install transformers and let it pull whichever tokenizer the checkpoint specifies. Drop down to the dedicated tokenizer libraries only when training a new tokenizer or benchmarking encoding speed. Interpretability libraries are heavier dependencies; nnsight in particular pulls a substantial transitive dependency set, so consider isolating it in a dedicated environment.

Drift in model SDKs

Frontier APIs ship breaking changes every 6 to 12 months. tiktoken's o200k_base encoding now covers GPT-4o and GPT-5 variants; older notebooks pinning cl100k_base still work for GPT-4 Turbo but undercount GPT-4o tokens by 5 to 10 percent on average. Always check the model card.
