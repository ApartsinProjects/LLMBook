## Methodology

"Atomic" = element cannot split across a page boundary in
EPUB/Kindle. Determination follows the CSS audit in
`AUDIT_reflow.md` (load order book.css then
epub_overrides.css). A block is "tall" if its estimated
rendered line count exceeds the per-category threshold.
Heights are estimated from text length (~70 chars/line),
`<p>` count, `<tr>` count, `<li>` count, `<pre>` newlines,
and SVG viewBox height (capped at one Kindle page since
epub_overrides.css limits images to 90vh).

## Blocks That SHOULD Stay Atomic

- `.callout.key-takeaway` blocks under 4 lines remain
  atomic (none currently exceed this in the book).
- `.chapter-header` banners (small, intentional).
- `<tr>` rows (already row-level atomic).
- Single `<img>` / `<svg>` inside a figure (90vh capped).
- Single `.katex-display` (one rendered formula).
- `<figure>` wrappers when their TOTAL content (incl.
  caption) fits within one Kindle page, regardless of how
  tall the SVG is on the web - the 90vh cap protects them.
