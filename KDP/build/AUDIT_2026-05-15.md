## 1. Navigation chain breakage (CRITICAL)

**Audit script**: `_audit_navigation_book_wide.py`
**Fix script**: `_fix_v901_nav_chain.py` (46 fixes)

### Worst offenders

| Module | Sections affected | Symptom |
| --- | --- | --- |
| **Module 28** (evaluation) | 11 sections | Chain scrambled: 28.2.next = 28.1 (loop), 28.3.next = 28.6 (skip), 28.6.next = 28.4 (backwards), 28.7.next = 28.1 (loop), 28.9.next = module-29 (skips 28.10-12) |
| **Module 30** (safety) | 3 sections | 30.10.prev = 30.3 (skip), 30.12.next = module-17 (cross-part backwards) |
| **Module 31** (strategy) | 2 sections | 31.5.next = 31.4 (backwards), 31.6.prev = 31.4 (skip 31.5) |
| **Module 12** (prompts) | 2 sections | 12.4.next = 12.2 (backwards) |
| **Module 14** (synth data) | 2 sections | 14.2.next = part-8/28.1 (cross-part jump) |
| **Module 16** (PEFT) | 4 sections | 16.4-16.7 chain broken |
| **Module 17** (RLHF) | 2 sections | 17.5 orphan (prev = book root) |
| **Module 21** (agents) | 2 sections | 21.1.next = 21.6 (skip) |
| **Module 24** (special) | 2 sections | 24.3.next = 24.1 (loop) |
| **appendix-T** | 1 section | T.1.prev = ../appendix-s/section-s.5 (should be index.html) |

### Root cause

Sections were renumbered/reordered over time but the prev/next chain was
not rebuilt. The `<nav class="chapter-nav">` block in each section was
hand-edited (or auto-generated) at content-creation time and never
refreshed when surrounding sections moved.

### Fix strategy

`_fix_v901_nav_chain.py` rebuilds nav chains based on actual file
numerical order:

  - section-N.1.html: prev=index.html, next=section-N.2.html
  - section-N.K.html: prev=section-N.(K-1), next=section-N.(K+1)
  - section-N.last.html: next = next module's index.html (computed
    from sibling-dir order, with letter-length sort for appendices
    so `a < b < ... < z < aa < ab < ...`)

| Module 28 (28.6, 28.7) | duplicate cards in trailing `<div class='section-grid'>` | already in main list |

### Root cause

Same as #1 — content was consolidated/renumbered and index pages kept
the old cards pointing to newly-renumbered files. Module 28 has the
worst case with 4 phantoms pointing to 28.1 alone.

### Fix strategy

`_fix_v902_phantom_cards.py`:
  1. Resolves all card hrefs to absolute paths (so `./section-X.html`
     and `../module-N/section-X.html` are recognized as duplicates).
  2. For each href group, keeps only the card whose title matches
     the actual section file's `<h1>`.
  3. Consolidates trailing `<div class='section-grid'>` cards into
     the main sections-list (dedup by resolved href).
  4. Re-sorts cards by section number (handles alpha prefixes like
     S.4, AB.5).
  5. Normalizes hrefs (drops `../$samemodule/` prefix).

## 3. Section-card CSS wrap bug ("S.1\\nvLLM..." breakage)

**File**: `KDP/build/epub_overrides.css` line 2108
**Status**: FIXED (this session)

### Root cause

`.section-card .section-title { min-width: 12em !important }` forced
the title element to be at least 12em wide. When the row width was
less than `2em (badge) + 12em (title) + padding ~14em`, the title
got pushed to a new line below the S.1 badge.

### Fix

Reduced `min-width` from `12em` to `4em` and changed `flex: 1 1 auto`
to `flex: 1 1 0` so the title shrinks to fit alongside the badge,
with internal text wrapping within its allocated space.

## 4. Math-in-paragraph bug (LOW count, but invalid HTML)

**Audit script**: `_audit_math_kpv_risks.py`
**Affected**: 1 case in `part-1/module-03/section-3.3.html`

### Root cause

Source HTML has `<div class="math-block">` nested inside a `<p>` tag.
HTML5 parser auto-closes the `<p>` before the `<div>`, leaving the
following text orphaned. This is the same pattern v810 fixed at
build-time, but for empty styled `<p>` wrappers around standalone
math-blocks. This case is different (math-block inside a non-empty
paragraph that surrounds it).

### Fix strategy

Either:
  (a) Source-edit section-3.3.html to split the paragraph around the math.
  (b) Add a new build hook that detects `<p>...<div class="math-block">...</div>...</p>`
      and splits into `<p>...</p><div class="math-block">...</div><p>...</p>`.

## 5. Stale section number labels (LOW count)

**Audit script**: `_audit_stale_section_numbers.py`
**Affected**: 1 file (`section-30.1.html` shows "32.1.1" through "32.1.12")

### Root cause

This section was renumbered from 32.1 to 30.1 but the internal TOC and
subsection labels still say "32.1.x". User-visible bug: TOC shows
"**32.1.1** OWASP Top 10..." when the section is actually 30.1.1.

### Fix strategy

Simple find-and-replace in section-30.1.html: `32.1.` → `30.1.`
(both in id attributes like `id="32-1-1"` and visible text).

## 6. Stale appendix-V references (V.4, V.5 don't exist)

**Audit script**: `_audit_stale_references.py`
**Affected**: 5 mentions in section-v.1.html and section-v.3.html

### Root cause

Appendix V was originally planned with sections V.1 through V.5, but
only V.1, V.2, V.3 were written. Inline references to V.4 (evaluation)
and V.5 (serving) remain in section-v.1 and section-v.3 prose.

### Fix strategy

Either:
  (a) Remove the references entirely (treat as future work).
  (b) Re-point to existing appendices that cover the content
      (V.4 → Appendix R/Experiment Tracking, V.5 → Appendix S/Inference Serving).

Recommendation: option (b) preserves the cross-reference intent.

table-level fix (since `table` is in the selector list).

No action needed unless KPV testing reveals specific tables that don't
flow. The v13.14 fix should already handle the user-reported case.
