## Simplification patterns (reusable)

### Pattern 1: 6-col comparison table → definition list

**Before:**
```html
<table>
  <thead><tr><th>Model</th><th>Params</th><th>Context</th><th>Cost</th><th>License</th><th>Notes</th></tr></thead>
  <tbody>
    <tr><td>GPT-4o</td><td>?</td><td>128k</td><td>$2.50/1M</td><td>Commercial</td><td>Best for X</td></tr>
    <tr><td>Claude 3.5</td><td>?</td><td>200k</td><td>$3/1M</td><td>Commercial</td><td>Best for Y</td></tr>
  </tbody>
</table>
```

**After (Kindle-friendly):**
```html
<dl class="model-comparison">
  <dt>GPT-4o</dt>
  <dd><strong>Params:</strong> ? · <strong>Context:</strong> 128k · <strong>Cost:</strong> $2.50/1M · <strong>License:</strong> Commercial. Best for X.</dd>
  <dt>Claude 3.5</dt>
  <dd><strong>Params:</strong> ? · <strong>Context:</strong> 200k · <strong>Cost:</strong> $3/1M · <strong>License:</strong> Commercial. Best for Y.</dd>
</dl>
```

### Pattern 2: Wide grid → split by category

If columns split naturally by topic (e.g. "costs" + "specs" + "performance"), present as 2-3 stacked narrower tables, each with the model name + 2-3 attributes.

### Pattern 3: Long verbose comparison → bulleted list per row

**Before:** 6-col table with paragraph-length cells.
**After:**
```html
<h4>GPT-4o</h4>
<ul>
  <li><strong>Strengths:</strong> reasoning, code generation, multilingual</li>
  <li><strong>Weaknesses:</strong> cost at scale, no on-device option</li>
  <li><strong>Best for:</strong> production agents needing top-tier reasoning</li>
</ul>
```

### Pattern 4: Transpose

If you have 8 columns × 4 rows, transpose to 4 cols × 8 rows. Now the wide axis is vertical (scrolls), narrow axis is horizontal (fits).

### Pattern 5: Mark as "complex — read on tablet"

For a few irreducibly wide tables (e.g. a hyperparameter grid), wrap in `<div class="complex-table">` and add a callout:

```html
<div class="callout note">
  <div class="callout-title">Complex Table</div>
  <p>This table is dense — for best readability, view on a tablet, computer, or in landscape orientation.</p>
</div>
```

### Recommended fix sequence

1. Tackle HIGH-severity files in order of count (most-table-heavy first)
2. For each table, pick the pattern that best matches the data shape
3. Test in Kindle Previewer at narrow portrait setting
4. For irreducibly wide tables, leave as-is and add the "complex" note

Estimated total effort to fix all HIGH-severity: ~30-60 minutes per file across most chapters; ~2 hours for the worst (appendix-v, appendix-h, fm-8).
