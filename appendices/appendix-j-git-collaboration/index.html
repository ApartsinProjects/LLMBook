Git, DVC, and Reproducibility

Version control, data tracking, experiment logging, and the practices that make ML work reproducible

Big Picture

Machine learning projects have unique version control challenges that standard software development workflows do not address well. Model weights are gigabytes in size. Datasets may be too large for Git. Results depend on random seeds, hardware, and library versions. This appendix covers the version-control tools and practices that bring order to this complexity: Git workflows for ML codebases, Data Version Control (DVC) for large artifacts, the patterns that link experiment runs to specific Git commits, and the reproducibility and CI/CD practices that make results trustworthy and shareable. Experiment-tracking platforms themselves (W&B, MLflow dashboards, model registries) live in Appendix K (Experiment Tracking).

Reproducibility is increasingly a professional and scientific requirement. A fine-tuning run whose configuration was not tracked cannot be reproduced, reported, or improved upon systematically. As LLM projects grow in scale and team size, the difference between ad hoc experimentation and a disciplined workflow becomes the difference between rapid iteration and recurring confusion about which checkpoint produced which result.

This appendix serves engineers and researchers who are comfortable with Git for software projects but have not applied version control discipline to ML artifacts. It is equally relevant for solo practitioners and teams working on shared LLM projects.

The reproducibility practices here directly support fine-tuning work in Chapter 18 (Fine-Tuning Fundamentals) and Chapter 19 (PEFT), where tracking configurations and checkpoints is essential. Experiment tracking concepts connect to evaluation workflows in Chapter 34. The production engineering practices of Chapter 35 assume the kind of disciplined artifact management this appendix establishes.

Prerequisites

Basic Git knowledge is assumed: committing, branching, and pushing to a remote repository. If you have never used Git before, work through an introductory tutorial first. The DVC and experiment tracking sections require a Python environment (see Appendix I) and familiarity with running CLI tools. No ML-specific knowledge is required for this appendix.

When to Use This Appendix

Read Section J.1 before starting any collaborative ML project. Add DVC (Section J.2) when your datasets or model checkpoints exceed what Git can handle. Section J.3 (Linking Experiment Runs to Git Commits) is essential before your first fine-tuning run; retrofitting commit linkage to an existing project is significantly more painful. Return to Section J.4 whenever a result cannot be reproduced or when preparing work for publication, and for the CI/CD wiring that ties model versions to automated deployment. For the W&B and MLflow tracking APIs themselves, jump to Appendix K. If your project is a solo API-calling script without training, this appendix can be deferred until you begin working with model artifacts.
