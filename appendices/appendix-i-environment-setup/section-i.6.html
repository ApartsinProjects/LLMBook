I.6 IDE Setup and Editor Integrations

Section I.6

Once your CUDA stack and Python libraries are in place (sections I.2 through I.5), the next decision is which editor or IDE you will spend your day inside. This is not a religious question; it is an engineering question, because the editor choice determines how productive you are with the specific workflows LLM engineering imposes: notebook-plus-script hybrid development, remote GPU instances, type-checked autocompletion against the HuggingFace and PyTorch APIs, and AI-in-IDE assistants that have rapidly become table stakes.

This section covers the four editors that dominate LLM engineering as of 2026: VS Code (the default), Cursor (the AI-first fork of VS Code), PyCharm (the heavy-duty alternative for refactoring), and Neovim (the keyboard-driven minimalist). The deep coverage of AI-in-IDE assistants for code generation lives in Chapter 50.2 (Vibe-Coding with LLMs); this section is the configuration counterpart focused on getting the integrations working. Notebook UX itself is in Appendix H Section H.3; API-key handling for AI assistants is in Section I.7.

Big Picture

Four editors handle 95% of LLM engineering as of 2026. VS Code is the default and the right starting point for almost everyone. Cursor is the AI-first fork that has moved fastest on agent-in-IDE integration. PyCharm is the right pick for projects with serious refactoring needs or strong existing JetBrains habits. Neovim is the right pick if you live in a terminal and have already invested in LSP plus a Lua config. All four can edit notebooks, attach to remote GPU instances, and run AI assistants; they differ in defaults, polish, and what they make ergonomic.

1. VS Code: The Default

VS Code (Microsoft, free, MIT-licensed core) is the most common editor for Python and LLM work as of 2026, with roughly 70% of the Stack Overflow Developer Survey's Python respondents reporting it as their primary editor. The defaults are good; the extension ecosystem is the largest; remote development (SSH, containers, WSL, Codespaces) works without configuration. The starter extension set for LLM engineering is small and stable.

Python (Microsoft) is the foundational extension; it provides interpreter selection, virtual-environment detection, debugger integration, and test runner UI. Pylance (Microsoft) is the language server that powers type-checked autocompletion; it understands type stubs for HuggingFace Transformers, PyTorch, LangChain, and most of the LLM stack as of 2025-2026 (the official type stubs landed across 2024). Set "python.analysis.typeCheckingMode": "basic" in .vscode/settings.json for inline type errors without the noise of strict mode. Jupyter (Microsoft) provides the notebook UI with kernel selection, variable explorer, and the cell-based debugger; combined with the %load_ext autoreload magic, this gives you a workflow where you iterate on library code in Python files and re-run cells without restarting the kernel.

Black or Ruff handle formatting and linting. Ruff (Astral, written in Rust) is the 2025 consensus pick because it is roughly 10x to 100x faster than the older flake8 / black / isort combination and handles all three concerns. Configure with a pyproject.toml entry; the Ruff VS Code extension picks it up automatically. GitLens adds inline blame and richer diff views; useful for tracing why a particular hyperparameter changed three commits ago when an eval regresses.

For AI-in-IDE, you have four current options: GitHub Copilot (paid, the most polished), Continue (open source, BYO-model, supports local models via Ollama), Cody (Sourcegraph, code-search-aware), and Codeium (free tier available). All four run as VS Code extensions; the deep comparison is in Chapter 50.2.

// .vscode/settings.json for LLM engineering
{
  "python.analysis.typeCheckingMode": "basic",
  "python.analysis.diagnosticMode": "workspace",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": {"source.fixAll.ruff": "explicit"}
  },
  "jupyter.askForKernelRestart": false,
  "notebook.output.textLineLimit": 200,
  "files.exclude": {"**/__pycache__": true, "**/.ipynb_checkpoints": true},
  "git.autofetch": true
}
Production Pattern: .devcontainer for Reproducibility

For teams sharing a codebase, commit a .devcontainer/devcontainer.json that pins the Python version, the CUDA base image, the installed extensions, and the post-create commands. New team members clone, open in VS Code (or Codespaces), and the entire environment rebuilds identically. The 2024-2025 HuggingFace example repos (transformers, peft, trl) ship devcontainers for exactly this reason; pattern after them.

2. Cursor: VS Code with Native AI

Cursor (Anysphere, freemium) is a fork of VS Code that integrates AI directly rather than via an extension. The differences from VS Code + Copilot are subtle but compounding: multi-file edits (Cmd-K applies an edit across N files in one operation), Composer (an agent mode that plans and executes multi-step changes), codebase chat (queries against your entire repo via embedded code search), and tab completion trained on a model that has more code-specific context than Copilot's default. As of 2025, Cursor supports both its hosted models and BYO-API-key for Claude, GPT, and other providers.

The trade-off: Cursor is closed-source where VS Code is open-source-core, and you depend on Anysphere's release cadence rather than Microsoft's. Most VS Code extensions work in Cursor (it is a fork, after all), so you do not lose the ecosystem. The 2025 production usage data Anysphere disclosed showed it as the editor of choice at multiple AI-native companies (Vercel, Replit, Perplexity), driven by Composer for agent-style multi-file refactors.

3. PyCharm: The Heavy IDE

PyCharm (JetBrains, Professional and Community editions; the free Community edition omits Jupyter and a few enterprise integrations) is the right pick for two situations: large refactoring projects where the cross-file rename and inspection capabilities matter, and teams already deep in the JetBrains ecosystem (IntelliJ, GoLand, WebStorm). Scientific Mode (Professional only) provides tensor inspection and a built-in plotting pane that fills the same role as VS Code's notebook variable explorer. The 2024 JetBrains AI Assistant (paid add-on) and the 2025 release of JetBrains' Junie agent provide an AI experience comparable to Copilot, with the JetBrains-specific advantage of deeper integration with the refactoring engine.

PyCharm's strongest point is the remote interpreter feature: configure a remote SSH interpreter pointing at a RunPod or Lambda GPU instance, and the IDE runs your code there with full debugger, profiler, and Scientific Mode support, while you edit locally. The setup is heavier than VS Code's Remote-SSH but the resulting workflow is more cohesive for week-long fine-tuning projects.

4. Neovim: The Terminal Native

Neovim with LSP is the right pick if you already live in a terminal, have invested in a Lua config, and value the keyboard-driven workflow. The 2024-2025 ecosystem matured: nvim-jupyter (and the older jupytext-based workflow) provide notebook editing; nvim-dap integrates with debugpy for Python debugging; copilot.lua and codecompanion.nvim provide AI assistance. The trade-off is configuration complexity: you will spend more time on the editor itself, in exchange for an editor that does exactly what you want and runs over an SSH session to any machine.

6. Recommended Starter Setup

For 90% of readers starting LLM engineering today, the recommended setup is:

  1. Install VS Code (or Cursor if you are committing to AI-first workflows from day one; the two are interchangeable enough that switching later is easy).
  2. Install the Python, Pylance, Jupyter, Ruff, and GitLens extensions.
  3. Pick one AI assistant: Copilot (paid, polished), Continue (free, BYO-model), or Cursor's native AI (free tier).
  4. Drop the .vscode/settings.json from the code snippet above into your project.
  5. If you work on a remote GPU regularly, install Remote-SSH and verify you can open a folder on the remote machine.

A typical configured workspace looks like this: the editor pane shows a Python file with type-checked autocompletion against the HuggingFace stack; the notebook pane to the right hosts a kernel where you iterate on training loops; the bottom panel shows a Ruff-cleaned terminal running nvidia-smi against the remote instance; an AI-assistant chat sits docked on the right edge for code-generation queries. The whole thing is reproducible because the .vscode/settings.json and .devcontainer/devcontainer.json are in Git.

The Two Jupyter Magics You Cannot Live Without

%load_ext autoreload followed by %autoreload 2 reloads imported modules on every cell execution; this is what makes the notebook-plus-script workflow ergonomic. %env CUDA_VISIBLE_DEVICES=0 pins the GPU when you have multiple cards (and the GPU-management discipline from the global instructions applies: only one GPU job at a time on a single-card workstation).

7. AI-in-IDE Configuration Hygiene

AI assistants in the IDE read your code, your file paths, sometimes your terminal output, and (depending on settings) send them to a remote API. For LLM engineering this matters more than for typical Python work because your source tree often contains proprietary prompts, embeddings, and eval-set examples that you do not want exfiltrated. Three defenses: (1) configure the assistant's workspace exclusions to skip data/, secrets/, and any directory containing API keys; (2) use the assistant's enterprise / business tier when available (Copilot Business, Cursor Business) which disable training-on-your-code by default; (3) verify the assistant respects .gitignore, which most do but some do not.

Key Takeaway
  • VS Code with Python, Pylance, Jupyter, Ruff, and GitLens is the right starter for ~90% of LLM engineers. Add one AI assistant (Copilot, Continue, Cody, or Codeium) and you have the working configuration.
  • Cursor is the AI-first fork of VS Code. Pick it if multi-file edits and agent-style refactors are central to how you work; the extension ecosystem is mostly compatible.
  • PyCharm Professional is the right pick for heavy refactoring projects or teams already in the JetBrains ecosystem; Scientific Mode and full remote interpreters are the differentiators.
  • Neovim is the right pick for terminal natives; the 2024-2025 LSP and Jupyter ecosystem make it viable, but the configuration cost is real.
  • Commit your .vscode/settings.json and a .devcontainer/devcontainer.json to your repo so the team's environment is reproducible. AI assistants should be configured to skip data and secrets directories before you point them at the codebase.
