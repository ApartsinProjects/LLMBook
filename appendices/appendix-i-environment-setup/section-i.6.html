I.6 IDE Setup and Editor Integrations

Section I.6
Section under construction

This section is a placeholder for the IDE-setup material previously scattered across H.3 (Jupyter in editors), I.1 (workspace hints), and I.5 (cloud notebooks). It will consolidate editor configuration into one canonical home. The content below is a stub describing what the finished section will cover; the prose will be filled out in a subsequent pass.

Once your CUDA stack and Python libraries are in place, the next decision is which editor or IDE you will spend your day inside. This section covers the integrations that matter for LLM work: GPU-aware debuggers, kernel selection for notebooks, type-checked autocompletion against the HuggingFace stack, and remote development against cloud GPU instances. It excludes general Python tooling (covered in Appendix H) and CUDA-toolkit setup (covered in Section I.2 and I.3).

Planned Coverage

  • VS Code with the Python and Jupyter extensions. Kernel selection per project, the variable explorer, attaching the debugger to torch.distributed processes, and using .devcontainer for reproducible toolchains.
  • Cursor and Copilot-class editors. Workspace context configuration for the HuggingFace and PyTorch APIs, retrieval-augmented completion settings, and keeping inline AI suggestions from accidentally leaking proprietary tokens (a hand-off to Section I.7).
  • JetBrains PyCharm. Conda interpreter selection, Scientific Mode for tensor inspection, remote interpreters over SSH, and the run-configuration trick for one-click torchrun launches.
  • Jupyter inside an IDE. Why %load_ext autoreload and %env CUDA_VISIBLE_DEVICES are the only two magics you cannot live without, and how to attach the kernel to a remote machine through SSH tunneling.
  • Remote / cloud development. GitHub Codespaces, VS Code Remote-SSH, JupyterLab on RunPod or Lambda, and the bare-minimum extensions that survive a fresh instance.
  • Workspace hygiene. Project-local .vscode/settings.json patterns that pin the Python interpreter, suppress notebook output diffs in Git, and surface pyproject.toml lint rules in the editor.
Pairs with

This section pairs with Appendix H Section H.3 (Jupyter Notebooks and Google Colab), which covers the notebook UX itself. The editor integrations described here are about getting that UX to work in your local or remote IDE. API-key handling for AI-coding assistants is in Section I.7.
