Appendix M: Master Reference Tables

Why this page exists

Practitioners build LLM systems by making 15 or so recurring decisions: which model to call, which RAG architecture, which PEFT method, which agent framework, which alignment method, which decoding strategy, where to put knowledge, how to evaluate. Each decision has a half-dozen viable options with non-obvious tradeoffs. This page is the single reference card for those decisions. Each table also appears in its primary chapter; this is the index.

How to use these tables

Each table answers one of the questions below. Click through to the source chapter for the deeper treatment; come here for the scannable comparison.

  • T1: Four-Tier Intervention Hierarchy, "Should I prompt, RAG, fine-tune, or pretrain?"

T1: The Four-Tier Intervention Hierarchy

Source: Part III opener. When a model is not doing what you want, climb the cheapest rung first.

TierWhat changesCompute costTime to deployGeneralization riskUse when
1. PromptingJust the prompt; weights frozenNone (one extra inference)MinutesNoneThe model already has the capability and you just need to elicit it
2. RAGRetrieved context; weights frozenEmbedding + searchHours to daysLow (additive)You need fresh, verifiable, or domain-specific facts
3. Fine-tuning / PEFTSome weights (or adapters)$10s to $100s for LoRA, $1k+ for full FTDays to weeksMedium (catastrophic forgetting risk)You need to change behavior (style, format, refusal patterns), not facts
4. PretrainingAll weights$1M+ for a frontier modelMonthsHigh (you own it)You need a fundamentally different model (rare; usually a research project, not a product decision)

Heuristic: 80% of "I need to fine-tune" intuitions resolve to "I need a better prompt or RAG." Only escalate when the lower tier is provably insufficient on a held-out test set.
