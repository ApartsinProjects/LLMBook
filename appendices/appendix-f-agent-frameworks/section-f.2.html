Multi-Agent Patterns and Topologies in Practice

Section F.2

One agent is rarely enough. As soon as a task spans multiple skills (research plus writing, code generation plus review, planning plus execution), a single LLM context starts to fail: prompts get long, role confusion creeps in, and the model loses track of which sub-goal it is currently pursuing. The standard response is to decompose the problem into multiple agents, each with a focused role, a smaller context window, and a clear handoff protocol with its peers. The question is then which topology to wire them into.

This section catalogs the four multi-agent topologies that have stayed in production through 2024-2026 with the named cases that made each pattern famous. The conceptual taxonomy lives in Chapter 28 (Multi-Agent Systems); this section is the practitioner's reference for which pattern to reach for and which failure modes to expect when you do. The companion Chapter 27 (Tool Use Protocols) covers the MCP and function-calling primitives that the agents in these topologies use to interact with the world.

Big Picture

Four topologies cover 90% of production multi-agent systems: hierarchical (a manager dispatches to specialist workers), peer / debate (agents argue toward consensus), pipeline (sequential handoff with role specialization), and competitive (multiple agents solve the same task, best result wins). Each maps to a class of problems and has well-documented failure modes. The framework you pick (LangGraph, CrewAI, AutoGen, MetaGPT) is mostly a question of which topology that framework makes ergonomic.

1. Hierarchical: Manager Plus Workers

The hierarchical topology has a manager agent that receives the user request, decomposes it into sub-tasks, and dispatches each sub-task to a specialist worker. The manager is responsible for planning, sequencing, and result aggregation; the workers are responsible for executing one well-defined skill. This is the pattern that CrewAI popularized through its role-based abstraction and the dominant pattern in production content-generation systems.

CrewAI's idiom is to define each worker as a Role with a description, a goal, and a backstory; the manager (called a Crew) sequences tasks. The 2024-2025 production deployments include content-marketing teams at Mintlify and HubSpot, where a researcher agent gathers source material, a writer drafts the post, an editor refines for voice, and a fact-checker verifies claims before publication. The pattern works because each role is narrow enough that its prompt stays under 2k tokens, and the manager only needs to track which step is current, not the entire history.

from crewai import Agent, Task, Crew, Process

researcher = Agent(role="Researcher", goal="Find authoritative sources",
                   backstory="A meticulous research librarian.", tools=[web_search, arxiv])
writer = Agent(role="Writer", goal="Draft engaging prose",
               backstory="A former magazine staff writer.", tools=[])
editor = Agent(role="Editor", goal="Polish for clarity and voice",
               backstory="A senior copy editor.", tools=[])

crew = Crew(
    agents=[researcher, writer, editor],
    tasks=[Task(description="Research X", agent=researcher),
           Task(description="Draft post about X using the research", agent=writer),
           Task(description="Edit the draft", agent=editor)],
    process=Process.hierarchical,  # manager dispatches; alt: Process.sequential
)
result = crew.kickoff()
Production Pattern: Bound Manager Authority

The manager agent's prompt is the highest-leverage piece of the system. A loose manager ("delegate as you see fit") drifts into infinite re-dispatch loops; a tight manager ("you may call each worker exactly once, in this order") removes most of the value. The 2025 production sweet spot is to give the manager a small set of allowed actions (dispatch, aggregate, terminate) and a max-iteration cap, then let it plan within that frame. CrewAI's max_iter and LangGraph's recursion limits both enforce this.

2. Peer / Debate: Consensus Through Disagreement

The peer topology has multiple agents working at the same level, often with deliberately opposing roles (proposer and critic, optimist and pessimist, two domain experts), exchanging arguments until they converge on a synthesized answer. Du et al.'s 2023 paper "Improving Factuality and Reasoning in Language Models through Multiagent Debate" showed that this pattern measurably improves factual accuracy on benchmarks where a single agent confabulates. The 2024-2025 follow-ups extended the pattern to code review, where one agent proposes a fix and a second agent looks for bugs in the proposal before merge.

AutoGen (Microsoft Research, originally 2023, now AutoGen v0.4 / Agent-Stack as of 2025) is the framework most explicitly designed around peer conversation. Its GroupChat primitive lets you wire N agents into a shared transcript and define a speaker-selection policy (round-robin, LLM-routed, or rule-based). The 2024 production case study from Microsoft's GitHub Copilot Workspace team described using AutoGen for code-review workflows: a "proposer" agent suggests a refactor, a "tester" agent writes test cases against the proposal, and a "reviewer" agent looks for regressions; the loop terminates when reviewer issues no further critiques.

Failure Mode: Cascading Hallucinations

The textbook peer-debate failure is when the first agent says something false with confidence and the second agent, finding the assertion plausible, builds on it instead of challenging it. The Park et al. 2023 "Generative Agents" paper documented this in social-simulation runs, and the 2024 work from Anthropic on multi-agent debate (described in their alignment forum posts) extended the analysis. The mitigation that survives in production is to bind at least one agent to an external ground-truth tool (search, code execution, database lookup) so the conversation has something to anchor against. Pure LLM-on-LLM debate amplifies confident wrongness.

3. Pipeline: Sequential Specialization

The pipeline topology is the simplest: agent A's output becomes agent B's input, B's becomes C's, no branching, no loops. This is the pattern that MetaGPT (Hong et al., ICLR 2024) made famous by modeling a software development organization as a sequence of agents (product manager, architect, project manager, engineer, QA), each producing a structured artifact (PRD, design doc, task breakdown, code, test report) that becomes the next agent's input. The artifacts act as a coordination protocol: B only needs to read what A wrote, not the entire history of A's reasoning.

Pipeline is the right pattern when the workflow is genuinely linear and the skill boundaries are clear. The 2024 MetaGPT v0.8 release demonstrated end-to-end generation of small open-source projects (Snake game, calculator, blog scaffold) from a one-line spec, and the 2025 fork landscape includes OpenDevin (now OpenHands) which applies the same pattern to autonomous software engineering with tighter integration with shell execution and Git operations. Pipelines also dominate document-processing workflows: ingest agent extracts entities, normalization agent canonicalizes them, summarization agent writes the brief, classification agent routes to the right human reviewer.

4. Competitive: Race to the Best Answer

The competitive topology runs multiple agents on the same task in parallel and picks the best output by either a learned judge, a deterministic test, or majority voting. It is the multi-agent answer to ensemble methods in classical ML. The most public 2024-2025 examples come from coding benchmarks: self-consistency decoding (Wang et al., extended in 2024 to agent loops) generates N candidate solutions and votes, and AlphaCode 2 (Google DeepMind, 2024) explicitly used a sample-and-filter pipeline that generated thousands of code candidates and ranked them by passing test cases.

In production, competitive is the right pattern when the task is verifiable (you can run the code, check the JSON schema, validate the math) and the cost of running N agents is justified by the quality improvement. The 2025 work on best-of-N inference at Anthropic and OpenAI (with reasoning models drawing from a budget of intermediate thoughts and a learned verifier picking the best chain) is the same pattern internalized into a single model rather than orchestrated across agents.

6. Coordination Overhead: The Hidden Tax

Every additional agent adds coordination overhead: tokens spent on prompts that describe roles, on transcripts that carry context between agents, and on planning that humans would have just done in their head. The 2024 paper "Are More LLM Calls All You Need?" (Chen et al., NeurIPS 2024) showed empirically that for simple tasks (single-step Q&A, basic summarization), multi-agent systems are worse than a single well-prompted agent because the coordination overhead exceeds the specialization benefit.

The practical heuristic: do not reach for multi-agent until you have a single-agent baseline that is failing for an identifiable reason (context overflow, role confusion, repeated tool errors). If your single-agent baseline works, multi-agent is gold-plating, not engineering.

Postmortem: The Endless Crew

A pattern repeatedly seen in 2024-2025 CrewAI deployments: a hierarchical crew where the manager keeps dispatching the same task to the same worker because the worker's output looks "almost right but not quite." Without an explicit termination condition, the loop runs until token budget exhaustion. Fix: every Task gets a max_iter and every worker returns a structured artifact whose acceptance is judged by a deterministic check (schema validation, regex, hash match), not by another LLM call. The framework will not save you from runaway loops; you have to bound them yourself.

7. Framework Mapping

Most agent frameworks support multiple topologies but each has a sweet spot. LangGraph is the most general (it is a graph engine; you can wire any topology) but the most code-heavy. CrewAI is the most ergonomic for hierarchical and pipeline patterns thanks to its Role abstraction. AutoGen is the most natural for peer debate because GroupChat models the topology directly. MetaGPT is purpose-built for the software-engineering pipeline. For competitive / best-of-N, no framework dominates; teams typically wire it themselves around any of the above. Key Takeaway
  • Four topologies dominate production multi-agent systems: hierarchical (manager + workers), peer / debate, pipeline (sequential), and competitive (best-of-N). Pick by task shape, not framework preference.
  • CrewAI for content production, AutoGen for code review and debate, MetaGPT and OpenHands for software-engineering pipelines, sample-and-rank for verifiable competitive tasks. Each framework has a topology it makes ergonomic.
  • Coordination overhead is real. The 2024 Chen et al. result is that multi-agent loses to single-agent on simple tasks; only reach for multi-agent when you have a failing single-agent baseline.
  • Cascading hallucinations are the peer-debate failure mode; runaway loops are the hierarchical failure mode. Bind at least one agent to external ground truth, and bound every loop with max_iter and structured-artifact termination checks.
  • The manager prompt in hierarchical systems is the highest-leverage piece of the system. Tight, action-bounded managers beat loose "delegate as you see fit" managers in every documented 2024-2025 case.
