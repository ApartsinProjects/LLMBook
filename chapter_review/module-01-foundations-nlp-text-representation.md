# Module 01: Foundations of NLP & Text Representation

**Audit date**: 2026-05-11
**Sections reviewed**: 1.1, 1.2, 1.3, 1.4
**Total word count**: ~17,000

## Summary
A strong narrative chapter that genuinely traces the rise of representation-based NLP. The "four eras" framing in 1.1 is excellent and re-cited correctly throughout. Section 1.4's polysemy / ELMo arc is the chapter's high point: clear, motivated, and the BERT code substitution is well-justified. The chapter is hurt mainly by the same auto-link bug that affects module 0 (Softmax becomes "Section 4.1") plus a pile of duplicate or wrongly numbered figures and code captions, especially in section 1.3.

- **Duplicate Code Fragment captions.** `section-1.3.html` line 279 has TWO consecutive `<div class="code-caption">` elements: "Code Fragment 1.3.2: Measuring cosine similarity" immediately followed by "Code Fragment 1.3.15: Measuring cosine similarity". One of the two has to go.

## Gaps
- **Section 1.1's "Four Eras" diagram is rendered THREE different ways in a row** (illustration, staircase image, and a hard-coded styled HTML diagram). This is excessive and visually confusing — pick the best one and delete the others.
- **`section-1.3.html`** introduces the famous "king − man + woman ≈ queen" analogy (line 297) but never shows the underlying linear-algebra reasoning that makes it work. A 3-line "why this works geometrically" callout would close the loop.
- **CBOW** is mentioned briefly (line 156-159) but never explained in any depth, after the section explicitly says "Word2Vec comes in two flavors". If CBOW does not warrant a full subsection, it should be one sentence in a footnote, not a teaser that goes nowhere.
- **Section 1.2's `lemmatize`** code (line 122-130) explains in comments that NLTK lemmatizer defaults to noun and "running" stays as "running", but the *output block* (line 137) prints `['cat', 'running', 'quickly', 'beautiful', 'garden']` with "running" intact — the lesson is good, but where is the verb-POS-tagged contrast? The spaCy version on line 187 outputs `['cat', 'run', ...]`, which proves the point, but it is not labeled as the contrast.
- **GloVe and FastText are promised in the chapter index card** for section 1.3 but the section concentrates almost entirely on Word2Vec/Skip-gram. GloVe gets one paragraph at most, FastText one figure caption. The section title oversells.
- **No exercises in section 1.3 or 1.4.** Sections 1.1 and 1.2 have a "Quick Check" callout each. The pattern breaks for the second half of the chapter.
- **`section-1.4.html`** code (line 187+) uses `tokens.index(word) + 1`. The `+1` only works because `[CLS]` is a single token at position 0, but the warning that `index()` returns the *first* occurrence (so the code breaks for a sentence with the same word twice) is not stated.
- **Bibliography uses `Mikolov, T. et al. (2013). "Distributed Representations..."`** under "Tools & Libraries" in `index.html` line 177 — that is a paper, not a tool.

## Errors
- **`section-1.4.html` line 104** says LSTM is covered in `Chapter 00` ("a type of recurrent neural network… covered in Chapter 00"). That is wrong; LSTMs are covered in **Chapter 3**, section 3.1. Chapter 0 covers feedforward nets and gradient descent.
- **`section-1.3.html` line 175-180** introduces negative sampling as `log σ(v_context · v_center) + Σ_neg log σ(-v_neg · v_center)` but the variables `v_context`, `v_center`, `v_neg` are not defined anywhere; the formula assumes the reader already knows the dual embedding setup (each word has both an "input" and an "output" vector in Skip-gram).
- **`section-1.2.html` line 137** the printed output has "garden" lemmatized but the source list comprehension (line 122) only filters stop words and applies lemmatizer; "gardens" should also lemmatize to "garden" — that part is correct. But the displayed output **omits "across"** which is in the input — looks like an inconsistency between the comment "across" and the actual NLTK stop-word list (which contains "across" in some configurations). The output is actually correct given the default NLTK list (which contains "across"), but the inline comment on line 134 says the output is `['cat', 'running', 'quickly', 'across', 'beautiful', 'garden']` — that comment contradicts the actual displayed output `['cat', 'running', 'quickly', 'beautiful', 'garden']`. One of the two is wrong.
- **`section-1.3.html` line 279** the code claims `wv['cat']` and `wv['dog']` have cosine similarity ~0.76, but `wv` is the trained-from-scratch model on a 24-word toy corpus from line 245. With only 10 sentences, cosine ~0.76 is suspect; the printed numbers (0.7609 etc.) look fabricated. Use the pretrained Google News vectors (which the next snippet on line 295 actually uses) for these numbers, or rerun and report real numbers from the toy corpus.
- **`section-1.1.html` line 81** says "Computer vision 'solved' object recognition to superhuman levels by 2015" — the typical citation is the 2015 ImageNet paper (He et al.) crossing the human error rate of ~5% on classification (not "object recognition" broadly). "Solved" is too strong for a 2026-edition textbook.
- **Bib reference in 1.4** (line 165) says "weights are learned during fine-tuning for each specific task" — for ELMo specifically, the layer weights are learned during the *task-specific* training, but the term is not "fine-tuning" in ELMo's framing (ELMo predates BERT-style fine-tuning vocabulary; the original paper calls it "task-specific weights"). Minor but a teaching opportunity for a precision-conscious editor.

## Improvements
- **Cut the redundant "four eras" visualization in section 1.1** down to one figure. The styled box version is the most informative; delete the staircase illustration and the alt-text-only timeline.
- **Add a 100-word contrastive box to section 1.2** showing the same sentence preprocessed with three different pipelines (NLTK lemmatizer no-POS, NLTK lemmatizer with POS=v, spaCy) so the reader sees the exact differences.
- **Section 1.3 needs an "intuition" diagram for the king − man + woman analogy** — currently it is asserted as if it should obviously work, but no geometric explanation appears.
- **Combine sections 1.3 and 1.4 image cleanup** into a single pass: every figure caption, alt text, and image filename in the embeddings half of the chapter is misaligned. A 30-minute fix would dramatically improve the reading experience.
- **Add a "From Word2Vec to BERT" transition diagram** at the end of 1.4 that visually shows: one vector per word → contextual vector per token → contextual vector per token plus attention. This is the spine of the chapter and there is no synthesizing image.
- **Replace `tokens.index(word)` in section 1.4 code** with a comment-flagged version that handles WordPiece subwords properly; add the warning visible inline. The current code will silently break on "deposit" because BERT splits it into `dep` + `##osit`, and the section is *about* BERT.
- **Bibliography pass**: move Mikolov 2013 ("Distributed Representations") from Tools & Libraries to Foundational Papers in the chapter index. It is a paper, not a tool.
- **Add CBOW vs. Skip-gram side-by-side mini-diagram** with one sentence each. The "CBOW vs. Skip-gram" callout (line 156) is too thin; either expand or remove.

## One-thing-only fix
Repair section 1.3's image/caption/alt-text scrambling. As-is, three "Figure 1.3.5" callouts share a filename (`fig-1.3.5-cosine-sim.png`) but are placed under unrelated headings (Skip-gram architecture, negative sampling, cosine similarity), with alt text that contradicts both the caption and the visible image. This makes the most important section of the chapter functionally unreadable.
