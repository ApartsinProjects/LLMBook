Models

Section 71.4

For model selection, see Chapter 16's tier table; standardize on one tier across the team to keep eval results comparable.

71.4.1 Models behind product tools

  • Cursor: defaults to Claude / GPT family with user-selectable model per request. Cursor also ships in-house fine-tunes (Cursor-small, Composer) for low-latency edits and apply operations; users see them automatically without changing the request.
  • Claude Code: Opus 4.5 as the default high-quality tier, Sonnet 4.5 as the cost-efficient fallback. The Claude Code routing logic is documented in the Anthropic engineering blog.
  • GitHub Copilot: multi-model (GPT-5 family, Claude Sonnet, Gemini 2.5 Pro, o3 / o4-mini). The 2024-25 per-task routing logic (autocomplete vs chat vs agent) is documented in the GitHub Copilot docs.
  • OpenAI Codex (cloud): GPT-5 / o3-codex behind the cloud editor; the 2025 resurrection of the Codex brand for the cloud-agent product.
  • Magistral Medium and Magistral Small (Mistral, 2025): the right pick for self-hosted coding agents when proprietary APIs are off the table.

71.4.2 Model picks for embedded AI features

For embedded features (a "summarize this" button, an in-app chatbot), pick from Chapter 16's tiers. The workhorse tier (GPT-5, Claude Sonnet 4.5, Gemini 2.5 Flash) is the right default for almost all in-product AI features. Drop to mini/Flash tiers when latency matters; escalate to Opus 4.5 / GPT-5 only for genuinely hard reasoning tasks.

Long-running coding agents (Devin, Claude Code in agent mode, OpenHands) have requirements distinct from document summarization: they need 1M+ context to hold an entire codebase, lower per-token cost because they make many calls, and strong tool-call accuracy. Long-context cost is the dominant factor; Gemini 2.5 Pro and Claude with prompt caching are the two viable choices in mid-2026. For pure summarization the workhorse tier is fine and 200K context is plenty.
