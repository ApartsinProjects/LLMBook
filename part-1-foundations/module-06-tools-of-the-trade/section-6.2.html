Libraries & Frameworks

Section 6.2

The platform layer (Section 6.1) gives you tensors. To get from tensors to a working language model in fewer than a thousand lines of code, you stack libraries on top. This section lists the ones that show up in Chapters 0 through 5 and explains what each is responsible for.

6.2.1 Hugging Face transformers

The transformers library is the single biggest reason a graduate student can replicate a state-of-the-art result in a weekend. It exposes a uniform AutoModel and AutoTokenizer API across hundreds of architectures and tens of thousands of checkpoints on the Hugging Face Hub. For Part I, you use it to load BERT and GPT-2 and to study how each architecture exposes its forward pass.

The library has two layers: the modeling code (one Python file per architecture, intentionally hackable, see the "single-file" philosophy) and the higher-level Trainer / pipeline / generate helpers. The modeling code is the right place to learn how attention and feed-forward blocks fit together, because there is no hidden inheritance. The helpers are what you reach for in production. Appendix F covers the full ecosystem (Hub, Spaces, Datasets, Inference Endpoints).

6.2.2 tokenizers

tokenizers is the fast Rust-backed encoder/decoder library that ships alongside transformers. It implements BPE, WordPiece, Unigram, and SentencePiece variants with consistent training and inference APIs. Whenever you load a checkpoint through AutoTokenizer.from_pretrained, you are almost certainly using a tokenizers backend under the hood. Chapter 2 walks through how these algorithms actually work; here in Chapter 6 you are just installing the production implementation.

6.2.3 datasets

datasets streams large corpora without holding them in RAM. It is built on Apache Arrow, supports memory-mapped reads, and has connectors for thousands of datasets including FineWeb, C4, Wikipedia, and most academic benchmarks. The streaming mode (load_dataset(..., streaming=True)) lets you iterate over terabyte-scale corpora on a laptop, which is the only way Part I labs are even possible without renting cluster time.

6.2.4 Supporting cast

A few smaller libraries appear repeatedly in Part I labs and are worth installing once.

  • pandas: tabular preprocessing, evaluation result aggregation.
  • matplotlib and seaborn: plotting attention maps and loss curves.
  • tqdm: the only progress bar that has not gone out of fashion.
  • rich: structured logging and pretty tracebacks; saves time in long-running scripts.
  • pytest: unit-test the toy implementations you build in Chapters 3 and 4 before scaling them up.

6.2.6 Versioning and reproducibility

Pin everything. Transformers 4.x and tokenizers 0.x have made several breaking-but-quiet changes (default left-padding for decoder-only models, EOS handling in generate, the move from past_key_values tuples to Cache objects). A working notebook from 2024 may fail subtly on 2026 versions even though no exception is raised. Lock the versions in your environment file. Appendix D shows the lockfile patterns. For long-lived projects, also pin the model revision (the Git SHA on the Hub, not just the repo name) so a silent re-upload by the model owner does not change your results overnight.

Common gotcha

The transformers pipeline abstraction is convenient but hides decoding parameters and tokenization quirks. When a model behaves strangely (extra leading space, repeated EOS, wrong padding side), drop to AutoTokenizer and AutoModel.generate directly. The pipeline is for demos; the explicit API is for debugging.
