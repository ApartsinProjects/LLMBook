**Safe to auto-migrate book-wide** (all matches are high confidence):

- `lc_text_splitter` (1 hits): LangChain 0.3+: `from langchain_text_splitters import ...`.

**Needs review before migration** (mixed confidence):

- `pydantic_validator_v1` (0 high, 1 medium, 0 low): Pydantic v2: `@field_validator(...)` (per-field) or `@model_validator(...)` (whole-model).
- `lc_llmchain` (0 high, 0 medium, 1 low): LangChain 0.3+: prefer LCEL (`prompt | llm | StrOutputParser()`). `LLMChain` is deprecated.
- `hf_token_kwarg` (0 high, 0 medium, 1 low): Prefer the `HUGGINGFACE_HUB_TOKEN` env var or `HfApi(token=...)` at construction. The per-call `token=` kwarg still works but the env var is the canonical setup.
- `transformers_deprecated_task` (0 high, 6 medium, 0 low): transformers: `sentiment-analysis` -> `text-classification`; `ner` -> `token-classification`; `conversational` is removed in transformers 4.42+. Use the chat-template API on the model directly.

**Suggested order of operations:**

1. Run the auto-safe migrations first (mechanical text substitutions). These have zero false-positive risk by construction.
2. For medium-confidence Pydantic patterns (`.dict()`, `.json()`, `.parse_obj()`), spot-check each match to confirm the object is a `BaseModel` subclass. Many `.json()` calls are on `requests.Response` and must NOT be changed.
3. For LangChain `chain.run()` / `agent_executor.run()`, prefer `.invoke({...})` and ensure the input is wrapped in a dict so it round-trips through the Runnable interface.
4. For PyTorch `torch.save(model, ...)`, decide per-fragment whether the pedagogical point is checkpointing (state_dict) or full-pickle demo. Convert the former; leave the latter alone but add a comment.
5. For low-confidence matches, read the caption: if it explicitly demonstrates the legacy pattern as a contrast, leave it and consider adding `# deprecated: pre-vX` next to the line.
